# 🔌 Подключение агента через MCP

`tg-mcp` — это тонкий MCP-сервер поверх HTTP API. Запускается по stdio, работает с любым MCP-клиентом:
Claude Code, Claude Desktop, Cursor, Hermes, собственный агент на SDK.

Сервис при этом должен быть уже запущен: MCP не ходит в Telegram сам, он обращается к API на `127.0.0.1:8077`.

---

## Общий вид конфигурации

```json
{
  "mcpServers": {
    "Telegram": {
      "command": "/полный/путь/к/uv",
      "args": ["run", "--directory", "/путь/к/hermes-telegram-brain", "--no-sync", "tg-mcp"],
      "env": {
        "TG_API_URL": "http://127.0.0.1:8077",
        "API_TOKEN": "ваш API_TOKEN из .env"
      }
    }
  }
}
```

Три вещи, на которых спотыкаются чаще всего:

1. **Полный путь к `uv`.** Клиенты запускаются не из вашего шелла и `PATH` у них другой.
   Узнать: `which uv`, обычно `~/.local/bin/uv` или `/opt/homebrew/bin/uv`.
2. **Флаг `--no-sync` обязателен.** Иначе MCP-сервер при каждом старте будет пересобирать виртуальное
   окружение и драться за него с работающим сервисом.
3. **`API_TOKEN` должен совпадать** с тем, что в `.env`. При несовпадении инструменты вернут 401.

## Claude Code

Положите файл `.mcp.json` в корень проекта, где работаете:

```json
{
  "mcpServers": {
    "Telegram": {
      "command": "/Users/ваш-юзер/.local/bin/uv",
      "args": ["run", "--directory", "/Users/ваш-юзер/hermes-telegram-brain", "--no-sync", "tg-mcp"],
      "env": {
        "TG_API_URL": "http://127.0.0.1:8077",
        "API_TOKEN": "ваш токен"
      }
    }
  }
}
```

Проверка: `claude mcp list`, сервер должен показать `✓ Connected`.

## Claude Desktop

Тот же JSON в `~/Library/Application Support/Claude/claude_desktop_config.json` на macOS или
`%APPDATA%\Claude\claude_desktop_config.json` на Windows. После правки перезапустите приложение.

## Cursor

Тот же JSON в `~/.cursor/mcp.json` или в `.cursor/mcp.json` внутри проекта.

## Hermes

Добавьте блок в `mcp_servers` в `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  Telegram:
    command: /Users/ваш-юзер/.local/bin/uv
    args:
      - run
      - --directory
      - /Users/ваш-юзер/hermes-telegram-brain
      - --no-sync
      - tg-mcp
    env:
      PATH: /Users/ваш-юзер/.local/bin:/usr/local/bin:/usr/bin:/bin
      TG_API_URL: http://127.0.0.1:8077
      API_TOKEN: ваш токен
    connect_timeout: 60
    timeout: 180
    enabled: true
```

> ⚠️ Одной этой записи мало. Hermes отдаёт инструменты платформе только если имя сервера перечислено
> в `platform_toolsets`. Добавьте `- Telegram` в списки `platform_toolsets.telegram` и
> `platform_toolsets.cli`, иначе агент не увидит инструменты и пойдёт обходными путями.
> После правки: `hermes gateway restart`.

Проверка: `hermes mcp test Telegram`.

## Инструменты

### Чтение

| Инструмент | Что делает |
|---|---|
| `list_chats` | Список чатов: id, тип, название, число сообщений, последняя активность. Отсюда начинается почти любая задача |
| `chat_info` | Детали одного чата и диапазон сохранённой истории |
| `get_messages` | Лента сообщений с фильтрами по датам, отправителю, топику. Голосовые уже с расшифровкой, фото с описанием |
| `message_context` | Одно сообщение с соседями, цепочкой реплаев, ответами на него и альбомом |
| `search_messages` | Точный поиск по словам, русский и английский. Ищет и по расшифровкам, и по тексту документов |
| `semantic_search` | Поиск по смыслу через локальные эмбеддинги. Находит там, где слова не совпадают |
| `fetch_media` | Скачать файл и получить локальный путь, при необходимости расшифровать или распознать |
| `request_backfill`, `backfill_status` | Догрузить историю чата за период |

### Отправка, всегда через ваше подтверждение

| Инструмент | Что делает |
|---|---|
| `draft_message` | Черновик сообщения: текст, ответ на сообщение, вложения, отложенная отправка |
| `draft_edit` | Предложить правку вашего же отправленного сообщения |
| `draft_delete` | Предложить удаление вашего же сообщения |
| `outbox_cancel` | Отозвать неподтверждённый черновик, если агент передумал |
| `outbox_list` | Последние черновики с исходами, отсюда берётся id отправленного сообщения |
| `outbox_status` | Статус черновика: `pending`, `sent`, `scheduled`, `rejected`, `expired`, `failed` |

Ни один инструмент не отправляет сообщение сам. `draft_message` только создаёт запись, дальше карточка
уходит вам.

## Как это выглядит в работе

**Чтение.** Вы просите «посмотри, что писали в рабочем чате сегодня». Агент вызывает `list_chats`,
находит чат по названию, вызывает `get_messages`. Голосовые приходят уже текстом, фото с описанием
и распознанным текстом. Отдельно ничего дёргать не надо.

**Поиск.** «Найди, где обсуждали оплату» — это `search_messages`. «Что мы решили по проекту» без точных
слов — это `semantic_search`.

**Отправка.** «Ответь ему, что посмотрю вечером». Агент вызывает `draft_message` с текстом, id сообщения,
на которое отвечает, и причиной. Вам приходит карточка: кому, последние сообщения чата для контекста, текст,
причина, кто попросил. Нажимаете ✅, сообщение уходит от вашего имени. Агент видит результат через
`outbox_status`.

**Отложенное.** «Напиши ему завтра в 10, что КП готово» — `draft_message` с `schedule_at`. После
подтверждения сообщение попадает в штатные отложенные Telegram, где его видно и можно отменить руками.

## Если агент не видит инструменты

1. Сервис запущен? `curl -H "Authorization: Bearer $API_TOKEN" localhost:8077/health`
2. Проверьте вручную: `uv run --directory /путь/к/hermes-telegram-brain --no-sync tg-mcp` должен запуститься
   и ждать stdio, а не упасть с ошибкой.
3. Токен в конфиге совпадает с `.env`?
4. Путь к `uv` полный, не просто `uv`?
5. В Hermes: имя сервера добавлено в `platform_toolsets`?
6. Клиент перезапущен после правки конфига? Большинство читают конфиг только на старте.

Если клиент прячет инструменты за механизмом отложенной загрузки (как `tool_search` в Hermes), слабые
модели иногда теряют аргументы при вызове. Помогает модель уровнем выше.
